### A4

## 根因

`conftest.py` 的 `LabelType` 只定义了 `L1`–`L4` 四个键：

```python
class LabelType(Enum):
    L1 = allure.severity_level.BLOCKER
    L2 = allure.severity_level.CRITICAL
    L3 = allure.severity_level.NORMAL
    L4 = allure.severity_level.MINOR
```

而 CSV「用例级别」列（现已提交，commit `4f82d03`）写的是 `P1`–`P4`。收集用例时，级别单元格被转成 `mark.name="P1"`，报告钩子执行：

```python
allure.dynamic.severity(LabelType[mark.name].value)   # LabelType["P1"] -> KeyError
```

`KeyError` 落入 `except` 分支，全部回退成 `LabelType.L3.value`，即 `normal`。

## 修改

`conftest.py:91` 增加 P1–P4 映射，不动 CSV：

```python
class LabelType(Enum):
    L1 = allure.severity_level.BLOCKER
    L2 = allure.severity_level.CRITICAL
    L3 = allure.severity_level.NORMAL
    L4 = allure.severity_level.MINOR
    # mycase.csv「用例级别」列使用 P1~P4，映射到 Allure 标准 severity，
    # 否则 KeyError 会统一回退为 normal，报告无法体现真实优先级。
    P1 = allure.severity_level.BLOCKER
    P2 = allure.severity_level.CRITICAL
    P3 = allure.severity_level.NORMAL
    P4 = allure.severity_level.MINOR
```

映射关系：

| CSV 级别 | Allure severity | 报告“优先级” |
|---|---|---|
| P1 | blocker | blocker |
| P2 | critical | critical |
| P3 | normal | normal |
| P4 | minor | minor |
