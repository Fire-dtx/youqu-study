## 三个独立根因

**1. hook 重复注册（ERROR collecting）**
测试机上 `apps/autotest_my_app/widget/conftest.py` 是项目根 `conftest.py` 的**逐字节拷贝**（两者 md5 均 `43e39b603e501426d18da3adb589d248`，行号 171 都是 `pluginmanager.add_hookspecs(emoji_hooks)`），而**该文件不在 git 仓库里**（`git ls-files apps/autotest_my_app/widget` 无此文件，`setting/template/app_template/widget/` 也没有对应模板）。根 conftest 先注册 → widget 下再注册同一 `src.plugins.emoji_hooks` 模块 → pluggy 1.6.0 `HookCaller.set_specification` 抛 `ValueError: Hook 'pytest_emoji_error' is already registered` → pytest 直接放弃整个 `widget` 目录的收集（这也掩盖了下面第 3 条）。

**2. 模板占位用例（1 failed）**
`apps/autotest_my_app/case/test_mycase_001.py` 是框架 `manage.py startapp` 生成的演示用例（`src/startapp.py:67` 的 `rewrite()` 会把模板 `##` 前缀去掉，所以生成为可执行代码），走 `MyAppWidget.click_xxx_by_attr()` → 查找字面量 AT-SPI 元素 `"xxx"` → `ElementNotFound`。`mycase.csv` 里只有 001 没有 PMS 用例 ID，其余都有，佐证它是残留占位。

**3. 缺 JRE 导致报告生成失败（最终报错）**
`allure_custom` 内置 allure CLI（`allure-commandline-2.22.0.jar`，`bin/allure` 启动脚本），机器上既无 `java` 也无 `JAVA_HOME` → 脚本打印 `ERROR: JAVA_HOME is not set...` 后退出 → 不生成 `index.html` → `src/rtk/local_runner.py:367` 的 `AllureCustom.gen()` 在 `open(index.html)` 抛 `FileNotFoundError`。

附带发现：`apps/autotest_my_app/widget/test_mycase_007/009/011/013/015.py` 是 `case/` 同名文件的逐字节副本（同样不在 git 中），被第 1 条错误掩盖；修好 conftest 后它们会被收集，对同一批 PMS 用例 ID 重复执行（我曾观测到 19 passed）。已一并清理，使测试机与仓库零漂移（`diff -r` 除 `report/`、`__pycache__` 外无差异）。
