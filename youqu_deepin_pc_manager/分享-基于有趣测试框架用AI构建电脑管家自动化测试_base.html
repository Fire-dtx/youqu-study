A 类新增：让失败可定位

  • _lookup_log：单行四态日志——直接命中 / 真实未命中 / 候选命中 / 候选未命中，附 expr、name/role/size、耗时

  • 无 find_element_by_accessible_id：定位统一走 name 层级，减少多帧环境的不确定性
  • 无 GI 遍历判定活动帧（_active_frame_extents / _gi_find_descendants）：回到 dogtail 朴素递归

四个可复用的观察

  1. 任务形态决定模型。短任务海量并行用 deepseek-v4-flash；长会话重工具链用 v4.1-flash-1017；一次读 40k 行源码用 gpt-5.6-sol（9.0M 输入、0.015M 输出）。
  2. 吞吐与工具调用稳定性 > 单次推理深度。212 个定时会话全部由同一 flash 模型完成，每会话 1 轮。
  3. 缓存复用率是成本分水岭。交互 95.7%、无人值守 96.2%、建设期 6.4%；三条线合计 76.6%（2.05B / 2.67B）。
  4. 模型切换有成本。同会话跨模型丢上下文风格；统一主力后，文档与台账格式才稳定。

09 / LESSONS

12 条可复用的解决经验

每条都来自有日志、复跑结果或行为观察支撑的现场结论，可直接迁移到其他桌面应用自动化工程。

01

能力探测优于版本判断

pip、polkit、overlay、显示协议全部探测，不写 V20/V25 两套 if/else；版本号只用于报告标注。没机器验证的分支腐烂最快。

02

构建失败不静默回退

静默回退会制造"测试通过但测的是旧版本"的假象。部署后必须校验版本与源码一致，失败直接报错。

03

PASS 不是证据

以产品日志、D-Bus、系统状态为准；UI 只能证明"点到了"。AT-SPI 是操作通道，不是事实来源。

04

有界重试 + 提前退出

所有等待都要有超时、退出条件和现场信息。"看到就点 + 提前退出"，禁止用 continue 表达"再等等"。

05

四段闭环

构造 → 执行 → 断言 → 回退。finally 是硬约束；备份永不覆盖，发现遗留非空备份先恢复再重新备份。

06

负面状态自己构造

要求"缺失/异常"的用例自己造并回退，不依赖机器现状；"要求存在"的用依赖预检补齐，同一台机器两个方向各自自洽。

07

单一事实源

用例编号、优先级、期望以 PMS/登记表为准；csv、方法名、文件名三方校验，改完必须全量 --collect-only 验证唯一。

08

单入口串行

一把锁、一个入口、一条用例。并发是脏环境和误判的源头：拿不到锁直接 BUSY/SKIPPED，不抢跑。

09

证据链即交付物

台账、日志、复跑次数缺一不可；否则无法区分"用例错"和"产品错"。失败必须带根因与现场。

10

文档是 AI 的接口

写给下一位接手者（人或 AI）的实测笔记，比任何 prompt 都值钱：只写"已实测 / 未验证"，结论即时落盘。

11

环境故障与用例失败分账

SYNC/SSH/凭据失败记 blocked，不写 fail；失败率分母只算真正执行过的条目，否则缺陷被噪声淹没。

12

调度器也是被测对象

busy 比例、空转会话、reclaim 冲突、重复记录都要度量并优化；无人值守的吞吐由最弱的那个环节决定。

踩过的坑：每一条都有现场证据

只列根因明确、有日志或复跑结果支撑的条目。真正的瓶颈往往不是模型能力，而是信息、环境与调度。

建设期：信息门禁

并行 Agent 的瓶颈是"信息是否足够开工"

真机取证：AT-SPI 的能力边界

点击成功 ≠ 行为发生
  • QML 节点 showing 恒为 False，用例 PASS 但实际没执行检测 可见性改用 size != (0,0)；点击后必须看到运行态/结果态
  • V20 QML 不向 AT-SPI 暴露单项文本与状态 走产品 D-Bus：会话总线不认识时回退系统总线；都不实现才退回分项级断言
  • 修复完成弹窗永不消失，exec() 阻塞到 400–500s 每轮看到弹窗就点；命中关键字或窗口不可见即返回；统一收尾兜底
  • 弹窗正文读不到（DTK 标签 name 是对象名） 断言"弹框存在 + 标题 + 按钮文案"；正文从会话总线请求参数取

部署：环境前提要编码进脚本

桌面自动化的失败大多不是用例错，而是环境差
  • Qt5/DTK5 依赖冲突，最终装成仓库旧版仍显示"成功" 只降元包、开发包解包到 /usr 不注册 dpkg；构建后校验版本；失败不静默回退
  • 测试机混入另一版本源，装包连带升级 SSH 失联 按系统版本写源、隔离不匹配源、备份独立目录、部署期间保持生效
  • V25 PEP 668 / pkg_resources 消失 / pipenv 装不上 能力探测：pip≥23 加 --break-system-packages，固定 setuptools<81，剔除 apt 同名包
  • V25 检测项 D-Bus AccessDenied polkit 双后端（pkla / rules_js）+ pkcheck 自检；预授权放在产品安装后
  • 39 个同名 .so 写进系统 site-packages，产品误报"关键库依赖问题" 框架依赖只装 .venv；PATH 前置；入口自动 execv 到 venv

判定与环境隔离

等价但可证，破坏性用例先隔离真实数据
  • 清理类用例误删测试机真实数据；备份覆盖造成永久丢失 前置把真实文件移出扫描范围，finally 按原路径恢复；备份永不覆盖
  • 同一机器两个实例 8s 并发，一个卸载另一个的 tmpfs 跨进程文件锁；拿不到锁直接 SKIPPED；内存构造余量 14% → 10%
  • 磁盘 96%、/boot 93%，环境越跑越脏 杀残留实例 + 删填充文件；日志/结果保留最近 30 份；磁盘阈值监控介入
  • 100MB 大文件正好卡在产品"大于 100MB"阈值 阈值类用例显式写边界，用 100 / 101 / 120MB 三档验证
  • 被 kill 时解析到旧 json，误报 passed 结论以退出码为准；json 时间戳必须晚于本次启动时间

无人值守：环境状态机

测试机在线、代码已同步、锁未过期、凭据有效，四者任一不成立产出即噪声
  • 64 / 212 个会话只领到 busy 就结束（30% 空转） 唤醒后先 status，busy 不建长会话；改为 watch 台账变化或指数退避
  • 测试机 04:12 失联，21 条仍被写 fail，失败率被放大一倍 台账增加 blocked 终态；SYNC/SSH/凭据失败不写 fail
  • 两个监控会话同时接管同一条，互相覆盖用例与 widget reclaim 携带 token 与基线版本；写前比对，冲突保留两版并记录合并人
  • 编排会话边汇总边想跑用例，工具错误累积 编排只做领取/汇总/决策；执行只由 worker 做

AI 协作：信任要设计出来

规程写死"证据优先"，比提醒模型更有效
  • 把"点了按钮"当"行为发生"；为变绿改判据 人保留验收权；产品缺陷记 fail + 根因 + 证据；放宽判据必须用户明确授权并留痕
  • AI 忘记回退，环境越跑越脏 规程强制 finally；残留检查脚本；每轮结束自查清单
